# Scout

Live opportunity discovery **and** admissions for Indian students — hackathons, internships, fellowships, scholarships, volunteering, conferences, plus real college / MBA / online-degree admission cycles. Scout finds what fits, ranks it against your actual record, and then **fills the applications**.

**Live:** https://opportune-six.vercel.app

---

## Architecture in one breath

A **zero-dependency** app. No build step, no framework, no `node_modules` — `public/` is served as-is and `api/` are Vercel serverless functions written against `node:` builtins and `fetch`. Deliberate: it deploys in seconds, never breaks on a dependency, and every file reads top-to-bottom.

```
timshel/
├── public/
│   ├── index.html            ← the shell (screens: onboarding · dashboard · main app)
│   ├── data/admissions.json  ← 96 researched admission cycles, served statically
│   ├── scout.js              ← THE APP (views, recommender, agent, apply flow, dashboard)
│   ├── scout.css             ← the design system (tokens, editorial layout, glass, motion)
│   ├── sw.js                 ← service worker (network-first navigations; never caches /api/*)
│   ├── extension/            ← Scout Autofill — MV3 browser extension (sync.js + fill.js)
│   ├── ext-test.html         ← harness that runs the real extension against a fake portal
│   └── scout-heart.png       ← the brand mark (never redrawn)
├── api/
│   ├── opportunities.js      ← 9-source live aggregator + scoring + 20-min rotation
│   ├── compose.js            ← raw LLM path for drafting + editing applications
│   ├── extract.js            ← vision model reads marksheets/certificates → structured fields
│   ├── enrich.js             ← reads a connected link and says what it proves
│   ├── ai-search.js          ← natural-language query → structured filters
│   ├── agent.js              ← intent router → ontology tools → grounded generative UI
│   └── _lib/                 ← feed.js · ontology.js · llm.js
└── scripts/dev.mjs           ← local server: serves public/ + routes /api/* to the handlers
```

Legacy from the v1 build (`supabase/`, `crawler/`, the Express deps in `package.json`) is unused by the running app.

## Run it locally

```bash
node scripts/dev.mjs 3001        # → http://localhost:3001
vercel env pull .env.local       # for the AI endpoints (optional)
```

## Deploy

```bash
vercel --prod --yes
```

**Cache discipline:** every frontend change needs `?v=N` bumped in `index.html` *and* the `CACHE` name bumped in `sw.js` — the service worker is stale-while-revalidate and will otherwise serve the old bundle one more time.

## Data & storage

- **Feed** — Unstop, Devpost, Devfolio, MLH, confs.tech, lu.ma, ConnectFor, WikiCFP, ArtIC. Keyless, live, re-ranked every 20 minutes.
- **Admissions** — `public/data/admissions.json`, generated by a multi-agent web-research run; every cycle labelled `VERIFIED-OPEN` / `UPCOMING` / `ESTIMATED`. Served as a static file; the client recomputes `open_now` / `days_to_close` against today so a cycle never claims to be open after it closed.
- **Everything the user owns lives in their browser.** No accounts, no server-side storage, nothing uploaded. Small records (profile, pipeline, drafts, chats) sit in `localStorage`; documents go in IndexedDB (`scout-docs`), which is the only place large enough. Profile → *Your data* exports a single JSON bundle — records *and* documents — as the backup and transfer mechanism.
- **Vercel is hosting plus five pure-compute functions.** No database, no state. The feed is edge-cached (`s-maxage=600`), so one invocation serves every visitor for ten minutes; the AI endpoints only run when someone asks for something.
